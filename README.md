# Сервис назначения ревьюеров для Pull Request

## Обзор проекта

Сервис автоматического назначения ревьюеров для Pull Request, позволяющий выполнять переназначение ревьюеров и получать список PR, назначенных конкретному пользователю, а также управлять командами и активностью пользователей.

## Реализованный функционал

- **Управление Pull Request:**
  - Автоматическое назначение до двух активных ревьюеров из команды автора при создании PR
  - Переназначение ревьюеров на случайного активного участника из той же команды
  - Получение списка всех PR, назначенных конкретному пользователю
  - Идемпотентная операция Merge PR с защитой от изменений после слияния
- **Управление командами и пользователями:**
  - Создание и получение команд
  - Управление флагом активности пользователей
  - Массовая деактивация пользователей команды
  - Автоматическая блокировка назначений неактивных пользователей на ревью
- **Аналитика:**
  - Получение статистики назначений по пользователям и по PR
- **Валидация данных:**
  - Проверка правильности входных данных.
- **Логирование:**
  - Настроено логирование событий сервиса.
- **Тестирование:**
  - Реализованы E2E-тесты и нагрузочный тест.

## Стек технологий

Go, PostgreSQL, Docker, Swagger, pgx, ogen, chi, Vegeta.

## Архитектурные особенности

Проект использует **API-first подход**: HTTP-сервер, клиент и модели данных генерируются автоматически из спецификации OpenAPI с помощью [ogen](https://github.com/ogen-go/ogen).

Преимущества:

- Типобезопасность на уровне компиляции
- Автоматическая валидация запросов/ответов
- Синхронизация документации и кода

## Запуск проекта

Используйте Makefile:

```bash

```

Или напрямую Docker Compose:

```bash
docker compose up -d --build
```

- Документация: `http://localhost:8080/docs`.

Остановка:

```bash
make down
```

Или

```bash
docker compose down
```

## Принятые проектные решения

- Флаг активности влияет только на выбор ревьюеров, а автор PR может быть как активным, так и неактивным.​
- При деактивации или переводе пользователя в другую команду, если он назначен ревьюером в открытых PR, происходит попытка переназначения на другого активного участника команды. Если кандидатов нет — пользователь просто исключается из ревьюеров.
- При массовой деактивации пользователей команды они удаляются из открытых PR.
- Выбран формат UUID для всех идентификаторов.

Изменения в OpenAPI:

- format: uuid для всех полей с идентификаторами.
- Добавлены эндпоинты /health, /stats/assignments и /team/deactivate.
- Добавлены проверки minLength, maxLength и pattern для названий и юзернеймов.
- Добавлены коды ошибок 400 Bad Request и 500 Internal Server Error.
- Добавлены поля operationId, чтобы сгенерировались красивые имена методов.
- Код для ошибки "Team already exists" изменен на 409.
- Добавлен ответ 404 для /users/getReview.
- У /pullRequest/reassign в примере old_reviewer_id заменен на old_user_id.
